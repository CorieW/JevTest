# A small browser integration

Adapt this shape to selectors, routes, inputs, and requirements verified in the target application. Retain the import path generated by `init`; `../../../JevTest/dist/index.js` below is illustrative.

```ts
// JevTest checks for the application's local checkout flow.
import { checks, defineProject } from '../../../JevTest/dist/index.js'

export default defineProject({
  baseUrl: 'http://127.0.0.1:3000',
  ready: '[data-testid="app-ready"]',
  webServer: {
    command: 'npm run dev',
    url: 'http://127.0.0.1:3000/health',
    timeoutMs: 30000,
  },
  limits: { maxSteps: 12, timeoutMs: 60000, concurrency: 1 },
  flows: [
    {
      id: 'place-order',
      path: '/checkout',
      goal: 'Place one order for the seeded cart using customer@example.test.',
      inputs: { '#email': ['customer@example.test'] },
      completeWhen: '[data-testid="order-confirmation"]',
      checks: [
        checks.count('[data-testid="order-row"]', 1, 'Exactly one order exists'),
        checks.text('[data-testid="order-total"]', '£24.00', 'Order total is £24.00'),
      ],
    },
  ],
})
```

The application must keep the readiness marker visible at each relevant state. Seed the cart and isolate its orders through setup before using these expectations. If the displayed order can disagree with storage, add an authoritative check through the application's existing test API or database fixture helpers.

A custom check has this shape; the query and expected value come from the target application's integration:

```ts
// Compare the seeded account's persisted state with its specified outcome.
const savedOrderCheck = {
  name: 'One order is persisted for the test account',
  evaluate: async () => {
    const actual = await countOrdersForTestAccount()
    return { passed: actual === 1, expected: 1, actual }
  },
}
```

Scope queries to the current fixture rather than a global count. Keep the helper in `jevtest/`, implement it from the application's actual storage contract, and make it return safely before completion. Never expose assertion-only answers to Jev as hints for which action to choose.
